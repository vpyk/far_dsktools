# Как DskTools работает с образами

Чтение и запись образов делает библиотека [dsk_tools](https://github.com/Ptr314/dsk_tools): определение формата, загрузка секторов, файловые системы, каталоги, `get_file`/`put_file`/`delete_file`/`rename_file`, построение образа для сохранения. Плагин над ней:

- для **CP/M** сам определяет геометрию диска и проверяет каталог (`src/cpm_geometry.cpp`), ограничивает чтение и запись тем, что действительно есть на диске, показывает области пользователя папками и проверяет имена;
- для **всех форматов** решает, можно ли писать в образ, сохраняет его, следит за изменениями файла и приводит имена к допустимым в Windows;
- для **DOS 3.3**, **FAT**, **RT-11**, **140 Кб Агат/Apple II** восполняет то, чего библиотека не проверяет или делает иначе, чем нужно панели FAR.

## CP/M

### Почему плагин определяет геометрию сам

`detect_fdd_type()` выбирает тип CP/M только по расширению и размеру файла: `.kdi` в 819200 байт — всегда Корвет, `.fdd` того же размера — Орион, и т. д. Когда геометрия выбрана неверно (другое число системных дорожек, другой размер каталога, другое расположение сторон), вместо имён в каталоге мусор, а `fsCPM` читает блоки не там. Пример — `DASIC2.KDI`: каталог лежит за тремя дорожками одной стороны, а не за одним цилиндром, как у Корвета.

Поэтому `find_cpm_geometry()` (`plugin.cpp`) вызывается для каждого сырого образа (`FILE_RAW_MSB`) с типом `TYPE_CPM:*` и для каждого файла, который библиотека не опознала. Образы CP/M в других контейнерах (HFE, MFM) и CP/M Агата/Apple II (`FILESYSTEM_CPM_DOS`, `FILESYSTEM_CPM_PRODOS`) идут так, как их видит библиотека. Плагин читает первые 32 байта файла и передаёт их в `cpm_geometry::find()`.

### Порядок поиска (`cpm_geometry::find()`)

1. **Таблица параметров в загрузочном секторе** (`read_boot_dpb()`). Орион, Корвет, Вектор, MicroDOS хранят в байтах 8–30 первого сектора описание диска, байт 31 — контрольная сумма (`$66` плюс сумма байтов 0–30). Раскладка та же, что у OdiWcx из OriZEmu:

   | Байты | Поле |
   |---|---|
   | `0A` | код размера сектора (128 << n) |
   | `0B` | сторон минус 1 |
   | `0C` | секторов на дорожке |
   | `0E` | дорожек на сторону |
   | `10`… | DPB: SPT, BSH, BLM, EXM, DSM, DRM, AL0, AL1, CKS, OFF |

   Таблица отвергается, если не сходится сумма, значения вне разумных пределов (BLM ≠ 2^BSH−1, SPT не равен секторам × размер / 128, OFF не меньше числа дорожек…) или она не подходит к файлу:
   - файл длиннее описанного диска **на целое число цилиндров, но не больше 4 на сторону** — геометрия берётся по дорожкам файла (Вектор форматирует 82 дорожки на сторону, а в таблице 80; иначе образ был бы только для чтения, а сохранение обрезало бы файл);
   - файл длиннее ещё больше — таблица не про этот диск (ПК8000: на дисках 800 Кб лежит таблица диска 400 Кб — 40 дорожек на сторону, DSM 195);
   - файл короче диска — допустимо (пустой конец обрезан), если в нём помещается каталог: загрузчик библиотеки дополняет недостающее байтами E5;
   - ширина номеров блоков (1 байт при DSM < 256, иначе 2), получающаяся из дорожек, отличается от той, что даёт DSM таблицы.

   Из таблицы строится diskdef с **одной головкой над всеми дорожками** (`heads = 1`, `tracks = дорожек × сторон`): OFF таблицы считает дорожки одной стороны, а `boottrk` двухголового diskdef'а библиотеки — цилиндры. Кодировки имён в таблице нет — берётся та, что у типа библиотеки (Вектор: `koi8_m`). DSM таблицы передаётся в diskdef параметром `dsm` (поддерживается библиотекой): многие диски считают блоков меньше, чем вмещают дорожки (`zexall.odi`: 388 при 389 возможных), и `put_file` не должен занимать блок, которого система диска своим не считает. Читает библиотека всё равно до последнего блока дорожек — файл, уже записанный туда другой программой, читается.

   **Таблица ПК8000** (8-битные номера при каталоге, который правильно читается только 16-битными): если с ней каталог читается с ошибками, плагин берёт её разметку (размер сектора и блока, каталог, системные дорожки) с дорожками diskdef'а библиотеки той же разметки и 16-битными номерами (Орион), без `dsm`. Так открывается и доступен для записи и обрезанный диск ПК8000 (`DISK10.FDD`).

   Таблица принимается, если каталог с ней выглядит правильным (см. ниже); для файла, который библиотека не опознала, — ещё и если в нём есть хотя бы одна живая запись.

2. **Геометрия библиотеки** (diskdef типа, который выбрал `detect_fdd_type()`), если с ней каталог выглядит правильным.

3. **Подбор**: все diskdef'ы CP/M библиотеки с размером образа, равным размеру файла, каждый ещё и с 0…8 системными дорожками, считаемыми по сторонам (`<diskdef>-sys<n>`); одинаковые раскладки пробуются один раз. Берётся вариант с лучшей оценкой, в каталоге которого есть живые записи.

4. Если не подошло ничего — образ открывается так, как его видит библиотека, с пометкой «каталог похож на повреждённый».

Найденная геометрия регистрируется в общем наборе diskdef'ов плагина (`diskdefs()` = diskdef'ы библиотеки + найденные) как `TYPE_CPM:BOOT-<сектор>-<секторов>-<дорожек>-<блок>-<каталог>-<OFF>-dsm<N>[-<кодировка>]` или `TYPE_CPM:<DISKDEF>-SYS<n>`, чтобы `mount_image()` перечитывал образ с ней же. Откуда геометрия, показывает Ctrl+L.

### Оценка каталога (`score_directory()`)

Каталог читается библиотекой (`dir()`) с кандидатной геометрией, каждая запись проверяется:

- ST (область пользователя) ≤ 31;
- имя и расширение — печатные символы; дополнение пробелами или нулевыми байтами (так пишут некоторые программы), после нуля — только дополнение; имя не пустое;
- XL ≤ 31, XH ≤ 63, RC ≤ 128;
- номера блоков — между блоками каталога и последним блоком дорожек; номер 0 — пустое место (0xE5 — обычный блок 229); при 8-битных номерах после пустого места не может идти номер (CP/M заполняет места по порядку, а 16-битные номера, прочитанные как 8-битные, дают «дыру» после каждого блока).

Каталог считается правильным, если плохих записей не больше одной на десять хороших (пустой каталог правильный); при подборе выигрывает наибольшее `хорошие − 10 × плохие`.

### Запись

Писать можно только с геометрией из загрузочного сектора или стандартной геометрией библиотеки, подтверждённой каталогом. С таблицей — только если её EXM, AL0 и AL1 совпадают с теми, что вычисляет библиотека (`fsCPM::fill_dpb()`): иначе файлы были бы записаны не так, как их ждёт система диска. Подобранная геометрия и «повреждённый» каталог — только чтение (причина в Ctrl+L, в заголовке панели `[R/O]`).

**Обрезанный образ** (файл короче диска) доступен для записи, если геометрия из загрузочного сектора. При сохранении (`keep_short()`) файл пишется до последнего байта, отличного от E5, с округлением до дорожки и не короче, чем был: отброшенный хвост — одни E5, которые загрузчик восстановит. После сохранения границы читаемых блоков (`set_cpm_bounds()`) сдвигаются к новому концу. Для других файловых систем обрезанный образ — только чтение: заполнитель E5 годится только для CP/M.

### Чтение

Перед `get_file()` плагин проверяет номера блоков файла (`cpm_blocks_ok()`: последний блок дорожек, блоки каталога; для CP/M Агата 140 Кб — 127 и 2). Файл с блоком за концом **обрезанного файла** не читается — вместо данных были бы байты-заполнители E5. Блок за концом диска библиотека сама отклоняет ошибкой чтения.

### Области пользователя

Библиотека перечисляет файлы всех областей одним списком и хранит номер области в `attributes >> 8`. Плагин показывает область 0 в корне, остальные (1–31) — папками `USER_nn`; записи с ST > 31 (метка тома, отметки времени CP/M 3) скрыты.

- F5 в `USER_nn` — запись в эту область (`put_file` с `fs = FS::CPM` и номером области);
- F7 в корне создаёт пустую область (до первого файла существует только в панели), F8 на `USER_nn` удаляет её целиком;
- F6 между двумя панелями одного образа и Alt+F6 (выбор области из списка) меняют только байт ST записей каталога (`file_set_metadata({"user", n})`): данные, имена и атрибуты остаются; совпадающий файл в целевой области — с вопросом о замене (библиотека этого не проверяет);
- при извлечении можно сложить все области в одну папку (опция диалога копирования).

### Имена

`put_file` и `rename_file` библиотеки проверяют только длину 8.3 в байтах UTF-8 и записывают байты как есть. Плагин (`cpm_name_error()`) допускает: до 8 символов, точку, до 3 символов; печатные ASCII без пробела и `< > . , ; : = ? * [ ] |`. Кириллица отклоняется, а не перекодируется: старший бит байта имени в CP/M — атрибут, а кириллицу КОИ-7 (Корвет, Орион) испортил бы перевод в верхний регистр. Совпадение имени при переименовании плагин тоже проверяет сам.

### Что делает библиотека

| | dsk_tools | плагин |
|---|---|---|
| Тип по расширению и размеру | `detect_fdd_type()` | проверяет по каталогу, заменяет при необходимости |
| DPB из diskdef'а | `fsCPM::fill_dpb()` | строит diskdef из загрузочного сектора, подбирает кандидатов |
| Чтение каталога, склейка экстентов | `dir()` | оценивает записи |
| Чтение файла | `get_file()`, ошибка для блока за диском | не даёт читать блоки за концом обрезанного файла |
| Запись, удаление, переименование | `put_file`, `delete_file`, `rename_file` | проверяет имена и совпадения, решает, можно ли писать |
| Смена области | `file_set_metadata("user")` | проверяет совпадение имени в целевой области |
| Дополнение короткого файла | `LoaderRAW` (E5) | сохраняет файл обрезанным |
| Ограничение DSM | параметр diskdef'а `dsm` | передаёт DSM из загрузочного сектора |

## Все форматы

- **Когда можно писать** (`read_only_reason()`): запись включена в настройках; у файловой системы есть запись (CP/M, DOS 3.3, FAT, RT-11); формат — сырой образ (`FILE_RAW_MSB`); размер файла равен размеру образа (нет заголовка; исключение — обрезанный CP/M, см. выше); у файла нет атрибута «только чтение». HFE, MFM/NIB/NIC, AIM, IMD не сохраняются намеренно: их writer'ы перекодируют все дорожки, нестандартные дорожки и защита пропали бы. Образы с заголовком (Агат 143360+128, `.rtd` с заголовком 256 байт) — только чтение: writer пишет буфер без заголовка.
- **Сохранение** — сразу после каждой операции: `create_writer()->write(buffer)` во временный файл `<образ>.dsktools-tmp`, затем `ReplaceFileW` (не `Writer::write(file_name)` библиотеки — он не принимает пути не в кодировке системы). При ошибке сохранения или ошибке библиотеки посреди операции образ перечитывается, изменения в памяти отбрасываются. По настройке — копия `<образ>.bak` перед первым изменением в панели.
- **Один образ в двух панелях** или изменённый другой программой: перед каждой операцией и при перерисовке панель перечитывает образ, если файл изменился (время и размер файла, счётчик сохранений этого FAR) — иначе одна панель затёрла бы изменения другой.
- **Имена** для панели и извлечения (`sanitize_name()`): недопустимые в Windows символы → `_`, имена устройств (`CON` → `CON_`), точки и пробелы в конце, совпадения без учёта регистра → `~2`. Каталоги открываются по записи библиотеки, найденной через показанное имя, а не по имени. Запись `..`, которую добавляют `dir()` DOS 3.3/FAT/ProDOS/Onix/Sprite OS, убирается — FAR добавляет свою.
- **Даты** (FAT, ProDOS, RT-11, Sprite OS): хранятся как местное время без пояса; плагин переводит их в UTC для FAR и обратно, ставит их извлечённым файлам и папкам и передаёт дату файла с диска в `put_file`/`mkdir` (сохраняют FAT и RT-11).

## Другие форматы

- **Агат/Apple II 140 Кб в порядке ProDOS** (`.po`): библиотека держит образ в порядке DOS 3.3 и при сохранении без имени файла пишет его обратно в порядке исходного файла — плагин поэтому не передаёт имя файла в `create_writer()`.
- **DOS 3.3**: `put_file` не находит и не заменяет файл с тем же именем — плагин проверяет совпадение сам и удаляет старый файл перед записью; `rename_file` не проверяет совпадение и обрезает имя — плагин проверяет и то, и длину 30 символов. Копия на месте (Shift+F5) сохраняет тип файла только в «родном» режиме `put_file`, который берёт имя из записи-источника, — поэтому копия получает старое имя, а источник затем переименовывается; папки создаются по имени.
- **FAT, RT-11**: при копии на месте имя берётся из `original_name` записи-источника — для новой копии плагин его убирает, вложенные записи копируются с прежними именами байт в байт.
- **RT-11**: том любой длины (например, диск УКНЦ без последнего блока) библиотека опознаёт по каталогу; такой файл короче диска — только чтение.
- **Удаление папок** — снизу вверх: библиотеки удаляют только пустые каталоги.
- **FIL** (отдельный файл Агата): у записи нет файловой системы (`FS::None`), копирование на месте её не использует.
